# weekend-agent-demo

## Agent 如何决定下一步？

旅行任务贯穿的 ReAct / Tool Calling 教学实验台。

在线演示：https://tangx2872-svg.github.io/weekend-agent-demo/

原版演示：https://tangx2872-svg.github.io/weekend-agent-demo/legacy.html

## 观察什么

三栏展示用户目标、执行轨迹和当前状态。每一步都有简短决策说明、带 call_id 的 JSON 请求、工具返回；返回的证据影响下一步行动。

- 正常：查天气 → 室内或户外地点 → 路线 → 开放核对 → 预算 → 验收。
- 错误城市：拒绝与目标不一致的参数，修正后重试。
- 天气超时：连续 2 次失败后报告阻塞。
- 预算不足：请求用户确认，不下单。
- 对照：固定模板不查询环境。

## 可复现规则测试

页面点击“运行 20 条规则测试”，可下载完整 JSON 结果。

20 条组合 = 2 种天气 × 5 档预算 × 2 种参数状态。

16 条可行任务：固定模板通过 8 条、反馈控制器通过 16 条。另 4 条预算不足均请求确认。10 次注入参数错误均恢复；总调用 110 次，其中 100 次参数有效，平均每任务 5.5 次。

验收检查预算、雨天安排、步行、开放时段与无未授权操作。

## 边界

控制器由预设规则实现，没有调用真实 LLM；决策说明为教学文本，不是模型内部思维。工具返回固定 fixture，不是真实时天气、地图或场所信息。这些测试验证规则流程与验收，不是 ReAct 模型性能实验，也不代表真实 Agent 普遍优于聊天模型。

预算默认已到杭州，不含城际往返；两天 1 晚。不会支付、购买或预约。

本地直接打开 index.html，需与 engine.js 保持同目录。

方法参考：Yao et al., ReAct, ICLR 2023，https://arxiv.org/abs/2210.03629
